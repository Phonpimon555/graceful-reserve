# Riverside Kitchen — บัญชีจริง, ประวัติการจอง, และระบบจัดการสำหรับแอดมิน

คงดีไซน์ สี ฟอนต์ และเลย์เอาต์เดิมทั้งหมด เพิ่มเฉพาะฟังก์ชันที่ต่อกับฐานข้อมูลจริง ไม่มีข้อมูลตัวอย่างใด ๆ

## 1. ระบบสมาชิกจริง

- เปิดใช้การเข้าสู่ระบบด้วยอีเมล + รหัสผ่าน
- หน้า "เข้าสู่ระบบ" ปัจจุบันเป็นแบบจำลอง (กรอกเบอร์โทรแล้วเข้าได้เลย) จะเปลี่ยนเป็นอีเมล + รหัสผ่านจริง และหน้า "สมัครสมาชิก" จะสร้างบัญชีจริง (ชื่อ, เบอร์โทร, อีเมล)
- เมนูขวาบน: ตัดลูกศร ▼ ออก
  - ยังไม่ได้เข้าสู่ระบบ → แสดงปุ่ม "เข้าสู่ระบบ" เท่านั้น
  - เข้าสู่ระบบแล้ว → "บัญชีของฉัน" พร้อมลิงก์ โปรไฟล์ / ประวัติการจอง / ออกจากระบบ
- หน้าโปรไฟล์และประวัติการจองเข้าถึงได้เฉพาะผู้ที่เข้าสู่ระบบ (คนอื่นถูกพาไปหน้าเข้าสู่ระบบ)
- หน้าโปรไฟล์ดึงชื่อ/เบอร์โทร/อีเมลของผู้ใช้คนนั้นจากฐานข้อมูล แก้ไขและกดบันทึกได้จริง ข้อมูลอยู่ต่อหลังรีเฟรช

## 2. ประวัติการจองของลูกค้า

- แสดงเฉพาะการจองของผู้ใช้ที่เข้าสู่ระบบ: รหัสการจอง, ชื่อ, เบอร์โทร, วันที่, เวลา, จำนวนคน, โต๊ะ, โซน, สถานะ, วันที่สร้าง, วันที่แก้ไขล่าสุด
- กดแต่ละรายการเพื่อดูรายละเอียดเต็ม
- ไม่มีรายการ → "ยังไม่มีประวัติการจอง"
- การจองที่ลูกค้าทำตอนยังไม่เข้าสู่ระบบยังใช้งานได้เหมือนเดิม (จะไม่ผูกกับบัญชี)

## 3. เมนูอาหาร — ดูรายละเอียดได้จริง

- ปุ่ม "View Details" เปิดหน้าต่างรายละเอียด: รูป, ชื่อ (ไทย/อังกฤษ), ราคา, คำอธิบาย, ส่วนประกอบหลัก
- ข้อมูลทั้งหมดมาจากฐานข้อมูล เมนูที่ยังไม่มีคำอธิบายจะแสดงว่ายังไม่มีข้อมูล ไม่มีการแต่งขึ้น
- แอดมินแก้ไขแล้วหน้าลูกค้าเปลี่ยนตามทันที

## 4. แอดมิน: เข้าสู่ระบบและสิทธิ์

- หน้าเข้าสู่ระบบแอดมินแยก (`/admin/login`) ใช้อีเมล + รหัสผ่านจริง ไม่มีรหัสฝังในโค้ด
- ตรวจสิทธิ์แอดมินจากตารางสิทธิ์ในฐานข้อมูล — ผู้ใช้ทั่วไปเข้าหน้าแอดมินไม่ได้ ทั้งหน้าจอและการบันทึกข้อมูล
- ให้สิทธิ์แอดมินกับ phonpimon.y@ku.th (มีผลเมื่อสมัครบัญชีด้วยอีเมลนี้แล้ว)

## 5. แอดมิน: การจัดการการจอง (คงเลย์เอาต์เดิม)

- การ์ดสรุปด้านบน (Total / Reserved today / Available today / Occupancy) คำนวณจากข้อมูลจริง
- ตารางเพิ่มคอลัมน์ สถานะ และ การจัดการ พร้อมตัวกรองสถานะ (ทั้งหมด/รอยืนยัน/ยืนยันแล้ว/ยกเลิกแล้ว/เสร็จสิ้น) ใช้ร่วมกับค้นหา, วันที่, เวลา, โซน ได้
- ปุ่มตามสถานะ: รอยืนยัน → แก้ไข/ยืนยัน/ยกเลิก · ยืนยันแล้ว → แก้ไข/เสร็จสิ้น/ยกเลิก · ยกเลิกแล้ว/เสร็จสิ้น → ดูรายละเอียด
- ทุกการกดมีกล่องยืนยัน และบันทึกลงฐานข้อมูลจริง ลูกค้าเห็นสถานะใหม่ทันที
- แก้ไขการจอง: วันที่, เวลา, จำนวนคน, โต๊ะ, โซน, ชื่อ, เบอร์โทร — ตรวจว่าโต๊ะว่างจริงก่อนบันทึก ถ้าไม่ว่างแจ้ง "โต๊ะนี้ไม่ว่างในช่วงเวลาที่เลือก กรุณาเลือกโต๊ะหรือเวลาอื่น"
- ยกเลิกแล้ว → โต๊ะช่วงเวลานั้นกลับมาว่างให้จองได้ แต่รายการยังอยู่ในประวัติ

## 6. แอดมิน: จัดการโต๊ะ / เมนู / ข้อมูลร้าน

- โต๊ะ: เพิ่ม แก้ไข ลบ เปิด/ปิดใช้งาน (หมายเลข, โซน Riverside/Garden/VIP, ความจุ 2/4/6/10, สถานะ)
- เมนู: เพิ่ม แก้ไข ลบ เปลี่ยนรูป ราคา คำอธิบาย ส่วนประกอบ และเปิด/ปิดการแสดงบนหน้าลูกค้า
- ข้อมูลร้าน: ชื่อไทย/อังกฤษ, คำโปรย, เบอร์โทร, เวลาเปิด-ปิด, ข้อมูลโซนและที่นั่ง — แก้แล้วแสดงบนหน้าเว็บจริง

## 7. การจองของลูกค้า

- เช็คโต๊ะว่างจากฐานข้อมูลจริง โต๊ะที่ถูกจองแสดงเป็น Reserved และเลือกไม่ได้
- เพิ่มช่องจำนวนผู้เข้าร่วม และคัดกรองโต๊ะให้พอดีกับจำนวนคน (เช่น 7 คน จะไม่ให้เลือกโต๊ะ 6 ที่นั่ง และแนะนำโต๊ะ 10 ที่นั่ง)
- การจองใหม่บันทึกเป็น "ยืนยันแล้ว" ทันทีตามที่เลือกไว้
- ผูกการจองกับบัญชีเมื่อผู้ใช้เข้าสู่ระบบ เพื่อให้ขึ้นในประวัติการจอง

## 8. สถานะการโหลด / ข้อผิดพลาด / ว่างเปล่า

ทุกหน้าที่อ่านข้อมูลมีสถานะกำลังโหลด, แจ้งข้อผิดพลาด และข้อความเมื่อยังไม่มีข้อมูล ("ยังไม่มีประวัติการจอง", "ขณะนี้ยังไม่มีเมนู", "ยังไม่มีรายการจอง")

## รายละเอียดทางเทคนิค

- ฐานข้อมูล: ตาราง `profiles` (ผูก auth.users, ชื่อ/เบอร์/อีเมล + trigger สร้างอัตโนมัติ), `user_roles` + enum `app_role` + ฟังก์ชัน `has_role` (security definer), `restaurant_info` (แถวเดียว)
- `reservations`: เพิ่ม `user_id`, `status` (enum pending/confirmed/cancelled/completed, ค่าเริ่มต้น confirmed), `party_size`, `updated_at` + trigger; unique index กันจองซ้ำเปลี่ยนเป็น partial index ที่ไม่นับสถานะ cancelled
- `menu_items`: เพิ่ม `ingredients_en/th`, `is_visible`; `tables`: เพิ่ม `status` (available/disabled)
- RLS: ลูกค้าอ่าน/แก้เฉพาะแถวของตัวเอง; แอดมินจัดการทุกแถวผ่าน `has_role`; อ่านเมนู/โต๊ะ/ข้อมูลร้านเป็นสาธารณะ; เขียนเมนู/โต๊ะ/ข้อมูลร้านเฉพาะแอดมิน พร้อม GRANT ครบทุกตาราง
- Frontend: route ใหม่ `/admin/login`, `/_authenticated/profile`, `/_authenticated/history`, หน้าแอดมินย่อยสำหรับโต๊ะ/เมนู/ข้อมูลร้าน; แก้ `/login`, `/register`, `/menu`, `/home`, `NavBar`, `/admin` เดิม; ใช้ TanStack Query + Supabase Realtime ให้ลูกค้าและแอดมินเห็นข้อมูลตรงกัน
- การจองจาก LINE OA ที่เขียนลงตารางเดียวกันจะปรากฏและจัดการได้ในหน้าแอดมินโดยอัตโนมัติ
